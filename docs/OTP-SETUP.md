# Подключение каналов подтверждения номера

Код доставляется каскадом: **Telegram → VK → SMS**. Порядок задаёт `OTP_CHANNELS` в `apps/api/.env`
(на сервере — в переменных окружения). Канал без ключей пропускается автоматически, поэтому
подключать можно по одному. Ключи в репозиторий не коммитятся — только в `.env` / секреты сервера.

Код: `apps/api/src/infra/otp/*`. Логи: при старте API печатает `Каналы OTP: telegram → vk → sms`,
на каждую отправку — `OTP → +7… через telegram`. В таблице `otp_challenges` колонки `channel`,
`provider_request_id` — по ним видно, каким путём ушёл код и сколько уходит в платные SMS.

## 1. Telegram Gateway (первый в каскаде)

Официальный сервис Telegram для отправки кодов по номеру телефона: https://gateway.telegram.org.
Доставляет только тем, у кого номер привязан к Telegram — перед отправкой API проверяет это
(`checkSendAbility`), поэтому попытка не тратится впустую.

1. Зайти на https://gateway.telegram.org и войти через свой Telegram-аккаунт.
2. Раздел **API** → скопировать **Access token**.
3. Раздел **Balance** → пополнить (тарификация за доставленное сообщение, порядка $0,01).
4. Опционально: **Sender** → указать `@username` канала/бота лиги, чтобы код приходил от имени бренда
   (нужно подтвердить владение).
5. В `.env`:
   ```
   TELEGRAM_GATEWAY_TOKEN=<access token>
   TELEGRAM_GATEWAY_SENDER=sindikat_league   # без @, опционально
   ```

## 2. VK (второй в каскаде)

Верификация номера сообщением ВКонтакте — продукт **VK ID / VK Verify** (кабинет https://id.vk.com/business,
раздел «Верификация»). Формат HTTP-запроса зависит от того, какой именно продукт подключат в кабинете,
поэтому адаптер (`vk.channel.ts`) держит URL и токен в конфигурации.

1. Зарегистрировать приложение в кабинете VK ID (нужны ИНН/реквизиты юрлица или ИП).
2. Включить услугу «Проверка номера телефона» / «OTP», пройти модерацию шаблона сообщения
   («Синдикат: код {code}»).
3. Получить **endpoint отправки** и **токен доступа** из кабинета.
4. В `.env`:
   ```
   VK_OTP_URL=https://…            # endpoint отправки из кабинета
   VK_OTP_TOKEN=<токен>
   VK_OTP_TEMPLATE=<id шаблона>    # если требуется
   ```
5. Прислать ссылку на документацию выбранного продукта — контракт запроса/ответа в адаптере
   сверяется с ней (10 минут правки), сейчас там контракт по умолчанию: `POST {phone, code, template}`
   с `Authorization: Bearer`.

## 3. SMS (последний рубеж)

Адаптер рассчитан на формат **SMS.ru** (`sms.ru/sms/send`, ответ JSON). Любой другой провайдер с
похожим GET/JSON API подключается заменой URL; иной формат — правка `sms.channel.ts`.

1. Зарегистрироваться на https://sms.ru, получить **api_id** (в правом верхнем углу кабинета).
2. Пополнить баланс.
3. **Имя отправителя** (например `SINDIKAT`): раздел «Отправители» → подать заявку, для России нужны
   документы юрлица/ИП. Без него код приходит с общего номера провайдера — для старта достаточно.
4. В `.env`:
   ```
   SMS_URL=https://sms.ru/sms/send
   SMS_API_KEY=<api_id>
   SMS_SENDER=SINDIKAT            # только после одобрения имени
   ```

## 4. Включить каскад

```
OTP_CHANNELS=telegram,vk,sms
```
В проде `console` из списка убрать и `OTP_DEV_CODE` удалить — универсальный код работает только
при наличии `console` в каскаде, но держать его на сервере незачем.

## 5. Проверить по одному каналу

Локально можно подключать реальные ключи, оставив `console` запасным:
```
OTP_CHANNELS=telegram,console
```
Дальше — запросить код на свой номер:
```bash
curl -s -X POST http://localhost:3000/v1/auth/otp/request -H 'content-type: application/json' -d '{"phone":"+79637686719"}'
```
Ответ `{"status":"sent","channel":"telegram","fallbacks":["console"],…}` и сообщение в Telegram —
канал работает. Принудительно проверить конкретный канал: добавить `"channel":"sms"` в тело.

Лимит — 5 кодов в час на номер (`MAX_PER_HOUR` в `otp.service.ts`), при тестах учитывать.

## Что видит пользователь

Экран кода в приложении и в кабинете показывает канал («код из Telegram») и кнопки
«отправить ещё раз» / «через ВКонтакте» / «через SMS» — запасные каналы из ответа `fallbacks`.
