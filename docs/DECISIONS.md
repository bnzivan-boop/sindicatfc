# Журнал решений

## Принятые при построении структуры

| # | Решение | Почему |
|---|---|---|
| A1 | pnpm-монорепо, `nodeLinker: hoisted` | Expo/Metro плохо работают с изолированным node_modules |
| A2 | NestJS 12 + ESM, TypeScript 6 везде | так генерирует актуальный CLI; одна версия TS в hoisted-дереве |
| A3 | Prisma 6 с `Unsupported(geography)` | PostGIS-типы без ORM-абстракции; точки пишутся raw-SQL |
| A4 | Элементы комплекта (удилище, катушка, леска…) — JSON-колонки в `gear_kits`, валидация zod | состав полей меняется часто, в фильтрах не участвует; каталог брендов/моделей — отдельные таблицы |
| A5 | SSE вместо WebSocket для live | однонаправленный поток, проходит через прокси, штатно в Nest |
| A6 | Единая сущность `catch` + `trophy` как «повышение» | по handoff §6.3 — без дублирования фото и параметров |
| A7 | Docker-порты 5433/6380/9010 | на машине заняты стандартные другими проектами |
| A8 | `POSTGRES_DB=postgres`, базу `sindikat` создаёт Prisma | иначе init-скрипт образа ставит расширения и migrate видит drift |
| A9 | Seed: Qualifier ×1,25 (как в прототипе) | временно, до решения #1 ниже; значение живёт в `ranking_rules`, не в коде |
